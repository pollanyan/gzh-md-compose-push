## 一、任务与结论摘要

需求：①分析「代码高亮」技能与「扫码认证、无需 AppID/AppSecret」技能的实现并提炼可复用思路；②盘点本机可用的公众号排版/推送专家、技能、连接器；③若无现成方案满足，实现一个可复用新技能（个人微信扫码认证、Markdown 多主题+预览、三段式确认、重复推送可选覆盖/新建）。

## 二、两个参考技能的实现方式（源码取证）

两个技能是技能市场包（本地未装），从市场详情接口拿到下载 URL，下载解压后只读分析。

### 1. Wechat Publisher（skill_2054902455876030464, v0.1.0）

- **实现**：Bash 包装 `wenyan-cli`（`@wenyan-md/cli`），核心命令 `wenyan publish -f article.md -t lapis -h solarized-light`。
- **代码高亮**：不是自己实现的——由 CLI 的 `-h` 参数选 highlightjs 主题（solarized-light / github / dracula / monokai 等），配合 Mac 风格代码块装饰。
- **主题**：wenyan-core 内置 default/lapis/phycat + 自定义 CSS 主题（`wenyan theme --add`）。
- **认证**：仍需 `WECHAT_APP_ID` / `WECHAT_APP_SECRET` + IP 白名单；frontmatter 强制 `title` + `cover`。
- **可复用思路**：①**主题与代码高亮主题解耦**为两个独立参数；②封面必填的实测约束；③`wenyan render`（只渲染不发布）可作为预览手段。

### 2. 公众号草稿箱推送（skill_2115386847996645376, v1.3.2, 森智道）

- **实现**：Python + `patchright`（Playwright stealth 分支）+ 独立 Chromium profile（`~/.config/gzh-md-compose-push/mp_profile/`，不落技能目录）。
- **认证**：个人微信扫码一次打开 `https://mp.weixin.qq.com/`，登录态存本机 profile 的 `Default/Network/Cookies`，长期复用；**完全不需要 AppID/AppSecret**，个人未认证号可用。
- **能力**：正文 HTML 注入、图片上传、封面设置、`--appmsgid` 覆盖草稿、回读核验；只点「保存为草稿」，绝不点「发表」。
- **关键技术事实（源码逐条取证）**：
  - 二维码元素是 `.login__type__container__scan__qrcode`，原图 ~122px 扫不出，脚本放大 4 倍截图；约 4 分钟刷新。
  - 2026 版编辑器无 iframe，正文是 `.mock-iframe-body .ProseMirror`。
  - 脚本路径 HTML 注入：`clipboard.write(text/html)` + `Cmd+V`（mac）/ `Control+V` + 点「继续插入」；合成 paste 事件 / 改 `innerHTML` 无效。工具路径 2026-11-26 实测 chrome-devtools 的 `press_key` 粘贴不触发，可用 `evaluate_script` + `execCommand('insertHTML')` 完成（全文保存重开核验通过）。
  - 图片库条目是 `<i>` 的 background-image，必须真实鼠标点击；刚上传未转码时选中会导致裁剪弹窗永远转圈。
  - 短文章注入判据用「预期非空白字符数」，不用固定 200 字魔数（否则短文被重复粘贴）。
- **可复用思路**：①扫码登录 + 本机登录态持久化；②剪贴板 HTML 注入；③覆盖草稿避免垃圾堆积；④「只写草稿不发表」的安全边界；⑤大量实测踩坑直接继承（已写入新技能 references）。

### 需求对应

1. **个人微信扫码认证**：`mp_full.py login` 截放大二维码给用户扫，登录态存本机 profile，无 AppID/Secret。
2. **Markdown 多主题 + 预览**：`md_to_gzh.py --all-themes --preview-dir` 生成 6 套主题页面 + index 选择页；选定后 `--theme <标识>` 生成正文。主题含高亮，`validate_gzh_html.py` 校验归零。
3. **三段式确认**：SKILL.md 强制流程——①主题方案 + 结构确认；②本地 HTML + 预览确认；③推送确认，每段停下等用户。
4. **重复推送覆盖/新建**：推送前 `mp_drafts.py list` 展示现有草稿，AskUserQuestion 问覆盖（带 `--appmsgid N`）还是新建；回读 `mp_check.py` 核验 PASS 才算成功。

### 正文插图自动上传（2026-11-25 补记）

- **入口**：`scripts/upload_md_images.py`，在排版前运行，输出新的 Markdown（原文件不动）。
- **覆盖范围**：Markdown 的 `![alt](src)`，src 可为本地路径、http/https URL 或 data URI；远程图下载、data URI 解码后统一落到临时目录。
- **上传与替换**：调用 `mp_imglib_upload.py` 批量上传到公众号图片库，按唯一文件名前缀取回 mmbiz URL，写回新 Markdown；后续主题预览与最终 HTML 都基于替换后的文件。
- **边界**：上传仍依赖公众号后台登录态；拿不到 URL 的图片保留原地址并报错退出。

### 官方接口备选通道（2026-11-25 补记）

- **入口**：`scripts/wx_api_publish.py`，纯标准库；凭证用环境变量 `WX_APPID` / `WX_APPSECRET` 临时提供，不写进脚本或文章。
- **命令**：`config-check`（凭证与连通性）、`push`（创建草稿）、`list` / `del`（草稿管理）、`clear-token`（换网络 / 换凭证后清缓存）。
- **安全边界**：只调用 `draft/add` 等草稿相关接口，不调用任何发布接口；排版前三段式确认与扫码通道完全一致。
- **错误口径**：40164 = 本机公网出口 IP 未进公众号白名单（微信按 TCP 源 IP 校验，改请求头无法绕过）；48001 = 账号无接口权限，个人未认证号常见，应改用扫码通道或先认证。
- **依赖**：不需要浏览器与 patchright；因此接口通道是「有凭证且账号有权限」时的备选，不是默认。

### 扫码通道：复用 Agent 的浏览器操作能力（2026-11-25 补记，2026-11-26 修订工具归属）

- **探测结论**：本机 Agent 的浏览器能力来自 `~/.workbuddy/mcp.json` 里的 `chrome-devtools` MCP（v1.12.0，含 `navigate_page` / `take_snapshot` / `evaluate_script` / `click` / `press_key` / `upload_file` / `take_screenshot` 等），配套 `chrome-devtools-cli` skill 可用 shell 脚本驱动；另有 `workbuddy-computer-use` 插件（截图 + 坐标 + 键盘）。`workbuddy-browser-use` 未安装。这是本机情况，不是技能前提：多数 Agent 装的是独立的 [chrome-devtools-mcp](https://github.com/ChromeDevTools/chrome-devtools-mcp)，也有宿主用其他等价工具/插件提供浏览器能力；技能按能力适配，不绑定具体宿主。
- **契约**：新增 `references/browser-tool-contract.md`，把公众号后台操作写成工具无关的单元（入口 URL / 选择器 / 剪贴板 JS / 保存判据 / 封面流程 / 核验），由 Agent 运行时翻译成当前宿主的工具调用。**自然语言只收集用户选择，不决定怎么操作页面**——这是「精确」的来源。
- **两种执行器同一流程**：工具路径优先（不装 patchright，用当前 Agent 浏览器工具的持久化 profile，多数由 chrome-devtools-mcp 提供；正文注入用 evaluate_script + insertHTML）；Agent 无满足契约的浏览器工具或工具无法执行 JS / 上传文件 / 独立 profile 时，退回 `mp_*.py` + patchright 执行同一组单元。computer-use 只能做扫码、按钮、上传，正文注入必须另有能执行 JS 的工具。
- **封面默认**：封面来源三选一（AskUserQuestion，2026-11-25 新增）——①用户自行提供（贴图 / 本地路径 / URL）②AI 自动生成（消耗生成额度需告知，按文章主题与配色出提示词，无文字、主体居中）③不加留空。①②统一经 `scripts/cover_prepare.py` 归一化为中心裁剪 900×383（2.35:1，AI 生成图水印随之去除）后再上传；不传则跳过，草稿封面为空；有封面则先存草稿拿 `appmsgid` 再重开设置（保存前设会静默失败）。
- **署名配置（2026-11-25 新增）**：配置项 `author`，由 `scripts/push_config.py` 管理（`path`/`get`/`set` 子命令），持久化在 `~/.config/gzh-md-compose-push/config.json`（环境变量 `GZH_PUSH_CONFIG` 可覆盖），**默认值 = 空字符串（署名留空）**。收集时机：第 1 步封面提问的同一轮 AskUserQuestion——先 `get author` 读配置，有值作默认可改，无值可跳过；提交后立即 `set` 持久化。读取方：`templates/article_template.py` 的 `AUTHOR` 自动从配置读取（模块内显式赋值可覆盖，优先级：模块显式 > 配置 > 默认空）；核验方：`mp_check.py` 以配置值为预期——配置非空须一致，配置为空则署名留空即 PASS（旧「署名必填否则 FAIL」规则废弃）。

### 关键修正：代码高亮拆行 bug

今天早些时候的截图问题（颜色保住但缩进错位、行距撑大）根因是**逐 token 一个 `<span leaf>`**：公众号编辑器把每个 leaf 当原子节点重排，导致 `export const X = [` 被拆成 5 行、缩进只挂在第一个 leaf。

新转换器改为**每行一个 `<span leaf>`，行内高亮用不带 leaf 的彩色 span**（实测校验 0 error / 0 warning）。示例结构：

```html
<p style="...Courier New...">
  <span leaf="">&nbsp;&nbsp;<span style="color:#15803D">"read"</span><span style="color:#71717A">,</span></span>
</p>
```

### 已固化的用户特殊约定（`references/user-conventions.md`）

按用户后续要求，把这次踩过的坑和个人排版偏好写进技能，转换器已实现、后续直接复用：

1. **超链接**：正文零 `<a>` 链接；全篇任意章节的链接统一编号，正文留「文字 + `[[N]]` 角标」，URL 只在文末 References 小节做纯文本。
2. **数字右上角**：`[[N]]` 引用角标渲染为 `#2563EB` 蓝色、`font-size:10px; vertical-align:super` 上标；取证来源要点列表也用蓝色名 + 蓝色上标。
3. **三层对照**：章节内「图 + 强/平/弱状态表」，状态列加粗，附说明（强=已覆盖/更优、平=有边界差异、弱=不可插件化）。
4. **表格列宽按内容适配**：`width="%"` 属性 + `table-layout:fixed` + `min-width:620px`，表头无底色、居中加粗、正文左对齐，窄屏可横滑，不无脑加宽到 900+。
5. **取证来源大章节**：`number_chapter("附","APPENDIX","取证来源")`，下接蓝色要点 + `### References` 纯文本 URL（两轮返工定稿）。
6. **版式**：全文字左对齐、正文零背景色（引用块例外：浅灰底 `#F5F5F5` + 柔和细线）、行内代码蓝 `#2563EB` 无底色、每段 1–3 处下划线、44px 大章节编号、小章节标题无竖线、签名区不写死人名仅末尾一处。
7. **代码高亮坑**：每行一个 leaf + 行内彩色 span（修复拆行/缩进错位），长行 nowrap + 外层 overflow-x:auto 可横滑，绝不图片化。
8. **标题与章节**：Obsidian frontmatter `title` 单独写成 `<!-- gzh-title: -->` 标记；正文有 `#` 就用 `#` 分大章，否则用 `##` 分大章，代码块里的 `#` 不算标题。
